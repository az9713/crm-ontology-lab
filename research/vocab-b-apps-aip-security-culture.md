# Palantir vocabulary B — applications, AIP, security, platform and culture

How to read this file:

- **"added"** in the term column means the term was not in the request list, but an FDSE would use it daily or the current docs put it next to a listed term.
- **"community-sourced"** means the term is internal slang or interview lore. The source is a job board, a blog, Blind, or a prep site, not Palantir docs.
- **Confidence**: high = a current Palantir page I opened says it directly. med = an opened page supports it only in part, or the main source returned 403 and I used a search snippet. low = I could not confirm it from an opened page.
- All quotes are 15 words or fewer.
- "CRM sentence" is an example of how an FDSE could talk about your CRM. It is a suggestion, not something you built.

## Interview process (FDSE)

Palantir does not publish an official description of the FDSE loop that I could find. Every fact below comes from prep sites and candidate reports. The round names are consistent across sources from 2022 to 2026. The order and the number of rounds change by role and candidate.

| Stage / round | What it tests (as reported) | Sources (opened) and dates |
|---|---|---|
| Recruiter screen (about 30 min) | Motivation for Palantir, mission fit, your past projects. One guide calls it an early hard cut. | aced.io guide (footer © 2026, "updated 11 days ago"): https://www.aced.io/guides/palantir-forward-deployed-engineer-interview ; techinterview.org (updated 2026-07-21): https://www.techinterview.org/post/3233476805/palantir-interview-process/ |
| Technical screen / online assessment | Live coding (CodePair or Karat) or a HackerRank test with coding, SQL, and sometimes a small API task (60–90 min). | aced.io; techinterview.org (same URLs) |
| Decomposition | You get a vague real-world problem. You break it into parts, define data and APIs, scope something buildable, and state trade-offs. Present in almost every loop; some candidates get it before and again during the onsite. | aced.io; techinterview.org; prachub candidate report (interview July 2026, published 2026-09-05): https://prachub.com/interview-experiences/palantir-forward-deployed-engineer-interview-referral-decomposition-and-long-decision-wait-9b717b5ca0 ; Blind 2022-01-08 calls it "system design (decomp)": https://www.teamblind.com/post/palantir-on-site-fdse-m7wtsqoh |
| Learning | You learn an unfamiliar library, API, or concept during the interview and extend it. Tests learning speed and how you use the interviewer and docs. | aced.io; techinterview.org; prachub (2026) |
| Re-engineering (the "debugging" round) | You fix bugs in, or extend, unfamiliar code (reported 200–500 lines). Tests systematic debugging and code reading. "Debugging" is the informal name, not a separate round. | aced.io; Blind 2023-02-05 (candidate solved 2 problems, asked how many pass): https://www.teamblind.com/post/palantir-re-engineering-round-dczjynds ; Blind 2022-01-08 "reengineering (debug)" |
| Coding | A data-structures and algorithms problem, often framed as a user feature. | aced.io; techinterview.org; prachub |
| System design | Architecture, data flow, APIs, trade-offs. More common for core SWE ("Dev") loops than FDSE loops. | aced.io; techinterview.org |
| Hiring manager (about 60 min) | Motivation, ownership of past work, and a second look at a weak onsite area. | aced.io; techinterview.org; prachub |

3. One search snippet (not opened) said AI use during interviews is prohibited. Assume it is.
